# Local stem preparation

Load a song into a deck, choose **Stems**, then **Prepare**. The app separates ordinary mono/stereo MP3/WAV songs locally and caches the five synchronized parts. It keeps music playing through the original audio path during preparation. The first preparation downloads the optional Windows CPU engine and separation models; later preparations reuse the engine/models, and prepared tracks reuse their cache after restart. No song audio is uploaded.

Click **Vocal**, **Instruments**, **Bass**, **Kick**, or **Hi-hat** to mute/unmute that part. Shift-click or right-click solos it; repeat the solo action to return to the previous mix. **Acapella** solos vocals, **Instrumental** restores all parts except vocals, and **Reset** restores the original mix. Changing stems does not seek, pause, stop effects or disable automatic playback. Controls apply to each deck independently. Selecting another pad mode keeps the current stem mix.

**Prepare** runs one background job at a time. **Cancel** stops that deck's preparation, including its worker process, and removes incomplete output. Preparation speed depends on track length and CPU; prepare songs before an event. The CPU engine uses two threads and a lower process priority. Missing internet or interrupted downloads leave normal music playback available and let you retry.

The models separate vocals/bass/accompaniment with Meta Demucs 4.0.1 (`htdemucs`), then kick/hi-hat with the community MDX23C DrumSep 6-stem model through OpenMIRLab's MIT inference code at revision `cb4779eedeca4f55ba498df8e234e2b5f4b90aaf`. **Instruments** includes the remaining accompaniment/percussion and reconstruction residual. Solo/mute quality varies with the recording and model; separated parts may contain bleed or artifacts. Full all-on playback uses the original decoder samples rather than the separated sum.

Data lives under `%LOCALAPPDATA%\GenAssist\DJSystemPro`: **StemEngine** holds the optional runtime, **StemModels** the verified model weights, and **Stems/v1** the content-addressed audio cache. A changed source or corrupted cached stem requires preparation again. Cached audio is stereo 48 kHz float WAV, about 115 MB per minute across five parts. Original audio files and the existing library document are not rewritten by preparation.

The engine ZIP contains replaceable CPython 3.12.10, PyTorch 2.10.0 CPU, Demucs 4.0.1 and the pinned MDX23C inference code with their dependencies and license files. Its `versions.json` records the exact packaged versions. The app downloads this official GenAssist engine artifact only after checking its pinned size and SHA256; it uses an isolated runtime and does not install Python system-wide. The Python executable's publisher signature is checked when creating the engine package. LGPL MP3 encoding bindings are omitted; NAudio decodes input to WAV before inference.

Model weights are downloaded separately from their upstream hosts and checked against pinned SHA256 values. They are not included in either public ZIP. Meta's Demucs code is MIT licensed. OpenMIRLab's MDX23C code is MIT licensed, but the DrumSep weights' original authors did not publish formal license terms. This personal-use feature does not establish permission for commercial use of those weights. See [the model provenance and license statement](https://github.com/openmirlab/mdxnet-infer#what-this-project-will-never-bundle) before commercial use.

The engine includes third-party licenses in its packages' `.dist-info` directories and CPython's `LICENSE.txt`. PyTorch's additional third-party notices are included in its package. Code sources: [CPython](https://github.com/python/cpython/tree/v3.12.10), [PyTorch](https://github.com/pytorch/pytorch/tree/v2.10.0), [Demucs](https://github.com/facebookresearch/demucs), and [MDX23C inference](https://github.com/openmirlab/mdxnet-infer/tree/cb4779eedeca4f55ba498df8e234e2b5f4b90aaf).
